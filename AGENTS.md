# AGENTS.md — working on B_Be_Bee-registry

A distilled guide for AI programming assistants and contributors working on `B_Be_Bee-registry`.

---

## 1. What this repository is

`B_Be_Bee-registry` is the decentralized metadata registry for the BBeBee music player ecosystem.
It is a **pure metadata index**:
- **Music & lyric sources**: Pointers only (`{username}-{name}.json`), pointing to author GitHub repos.
- **Plugins**: Pointers only (`<id>.json` — the file name is the plugin id), pointing to npm packages and author GitHub repos.
- **Themes**: Content in-repo (`themes/{author}-{name}/`), containing `theme.json` and `preview.png`.
- **Plugins resolve versions via npm**: Plugin entries carry no `version`; clients read versions from the npm packument of the package named in the entry's `npm` field.
- **One generated artifact**: `plugins/index.json` is generated by `scripts/build-index.mjs`, committed to the repo, and kept fresh by a CI gate. Its shape is `{ "entries": [...], "blocked": [{ "id", "reason" }] }` — `blocked` mirrors `blocklist.json`'s plugin ids (the client recall channel) and is always present. No other build output (`dist/`, etc.).

## 2. Commands

```bash
# Full validation (offline/sandbox falls back to warnings for unreachable networks)
node scripts/validate.mjs

# Strict mode (warnings treated as failures)
node scripts/validate.mjs --strict

# Skip network connectivity checks (syntax & schema validation only)
node scripts/validate.mjs --skip-network

# Negative test suite (verifies that invalid entries are blocked)
node scripts/validate.mjs --test

# Regenerate the committed plugin index (CI fails if the committed copy is stale)
node scripts/build-index.mjs

# Refresh the vendored service-key allowlist from the BBeBee repo's generated artifact
node scripts/sync-service-keys.mjs            # online, from GitHub raw (BBeBee main)
node scripts/sync-service-keys.mjs --from <path-to-BBeBee>/packages/protocol/service-keys.json  # offline
node scripts/sync-service-keys.mjs --check    # freshness check only (stale → exit 1)
# A sync that would SHRINK the key set (serviceKeys or criticalKeys) is refused
# by default — pass --allow-removals only when a removal is genuinely intended.
```

## 3. Four Entry Types & Schema Rules

### 3.1 Music Sources & Lyric Sources
Path: `music-sources/{username}-{name}.json` / `lyric-sources/{username}-{name}.json`
- **Required**: `id`, `name`, `repo`, `author`, `description`, `version`.
- **Optional**: `minAppVersion`, `params` (string[] — customizable parameter keys, e.g. `["sourceurl", "username", "password"]`), `platforms` (string[], subset of `desktop`/`mobile`; absent = all platforms).
- **Repo constraint**: Must match `https://github.com/<owner>/<repo>`, where `<owner>` equals `{username}` in the filename.
- **Reject unknown fields**.

### 3.2 Plugins (schema v2)
Path: `plugins/<id>.json` — the file name (without `.json`) **must equal** the entry's `id`; validation rejects a mismatch.
- **Required**: `id`, `name`, `repo`, `author`, `description`, `npm` (npm package name), `services` (string[] of Cordis service keys the plugin injects — may be `[]`; a key is valid when it is a core key in the generated allowlist vendored at `scripts/lib/service-keys.generated.json` **or** declared in the `provides` of another entry that itself passes validation (a rejected entry's `provides` never legitimize anything)), `platforms` (non-empty subset of `desktop`/`mobile`), `category`, `dependencies` (string[] of `"<id>"` or `"<id>@<semver-range>"`, may be `[]`), `compositors` (string[]), `i18n` (non-empty string[] of language tags, e.g. `["en", "zh"]`).
- **No `version` field**: removed in v2 — version truth lives on npm and inside the plugin package. Entries carrying `version` are rejected.
- **No `capabilities` field**: renamed to `services` in v2. Do not confuse registry `services` (Cordis service dependencies) with the plugin's own `BBeBee.plugin.json` `capabilities` (security gate: `fs:`/`net:`/`db:`…).
- **Dependency rules**: each id must resolve to an existing `plugins/<id>.json`; ranges use the hand-written parser in `scripts/lib/semver-range.ts` (subset: `*`, exact, `^`, `~`, comparators, `||`); dependency cycles fail validation.
- **Optional**: `provides` (string[] of Cordis service keys this plugin registers for other plugins — other entries may then list them in `services`; may be `[]`. Gates: keys on the **critical list** in the vendored artifact — `audio`, `codec`, `contentRegistry`, `db`, `downloads`, `fs`, `http`, `js`, `library`, `paths`, `player`, `plugin-manager`, `scanner`, `secrets`, `securityAudit`, `settings`, `store` — are reserved for builtin providers and may **never** be claimed; and each key may have **at most one** providing entry), `minAppVersion`, `screenshot` (https URL), `engines` (each value must be a valid semver range string), `homepage` (https URL), `reviewedVersion` + `reviewedIntegrity` (the reviewed pin: a semver version and its sha512 SRI; the pair must be declared together or not at all — CI verifies the pinned version still exists on npm with a matching `dist.integrity` and runs the content checks against the pinned version; a newer unreviewed `latest` only warns).
- **Category enum**: `ui-enhancement`, `notifications-integration`, `development-runtime`, `security-permissions`, `remote-mobile`, `marketplace-management`, `other`.
- **Compositors enum**: `now-playing.actions`, `now-playing.panel`, `now-playing.visualizer`, `track.context-menu`, `album.context-menu`, `library.sidebar`, `search.results-section`, `settings.sources`, `source.browse`, `topbar.tray`, `status-bar`, `tray`.
- **Uniqueness**: `id` is unique (it is the file name) and the `npm` package name must back **only one** entry.
- **Official entries**: an entry is *official* iff its `repo` owner is the GitHub account `BBeBeeX` — no other signal counts, and clients derive the official badge from the repo owner alone. The `bbebeex-` id prefix is reserved: claiming it with a foreign repo owner is a validation error. When CI supplies the PR author's org association (`BBEBEE_PR_AUTHOR_ASSOCIATION`), an official entry submitted by a non-OWNER/MEMBER is rejected; without that context the check is skipped and the skip is printed as a note. `CODEOWNERS` additionally requires @BBeBeeX review for official entries, `scripts/`, `.github/`, the vendored service-keys files, and `blocklist.json`.
- **Reject unknown fields**.

### 3.3 Themes
Path: `themes/{author}-{name}/`
- **Required files**: `theme.json`, `preview.png`.
- **theme.json required**: `id`, `name`, `version`, `author`, `description`, `tokens`.
- **Tokens**: Must contain `dark` and/or `light` modes (at least one). All values must be valid `#hex` colors (`#rrggbb`, `#rrggbbaa`, `#rgb`).
- **Contrast gate**: Must pass WCAG AA contrast requirements (normal text >= 4.5:1, bold/large text & components >= 3:1).
- Does not use `repo`.
- **Reject unknown fields**.

## 4. Acceptance Gate

Before finishing any change:
- `node scripts/validate.mjs` must output **0 errors**.
- Plugin entries: the `npm` field must name a package that exists on the **public** npm registry (CI fetches the packument; 404 fails the build — publish to npm before submitting the entry). CI also verifies the published package content (fetched via jsDelivr, at the **reviewed pinned version** when the entry declares one, else at `latest`): the `BBeBee.plugin.json` `id` and `package.json` `name` must match the entry, and the entry's declarations must be truthful — every `provides` key must actually be registered in the manifest's `contributes.services`, and if the manifest declares an `inject` array the entry's `services` must match it exactly.
- `node scripts/validate.mjs --test` must pass all negative tests.
- `node scripts/build-index.mjs` must leave `plugins/index.json` unchanged (CI enforces freshness via `git diff --exit-code`). validate.mjs **also** recomputes the index in memory and fails on any mismatch with the committed file — index consistency no longer depends on the CI step alone.
- **Blocklist**: `blocklist.json` (repo root) is the machine carrier of MODERATION.md's blacklist (`pluginIds` / `npmPackages` / `githubAccounts` / `repos`, each item with a `reason`). Any entry hitting any list is a hard validation error; the plugin ids are published as the index's `blocked` array so clients can quarantine already-installed copies.
- **Scheduled revalidation**: CI additionally runs `node scripts/validate.mjs --strict` online once a day (schedule trigger in `.github/workflows/validate.yml`), so post-merge drift — a changed pinned integrity, an unpublished package, a stale allowlist, a vanished upstream artifact — fails the workflow without any PR.
- **Service-key allowlist has exactly one source of truth, and it is not this repo.** The valid core keys are generated in the BBeBee repo from its plugin manifests (union of `contributes.services` plus the shell's `SHELL_MANIFEST`) and committed there as `packages/protocol/service-keys.json`. This repo vendors a copy at `scripts/lib/service-keys.generated.json` (loaded by `scripts/lib/service-keys.ts`) — never edit either file's key set by hand. `node scripts/validate.mjs` compares the vendored copy against the upstream artifact when online: provably stale is an error — including the upstream artifact answering **404** (a vanished source is never silently accepted); only a transport-level network failure degrades to a warning. Refresh with `node scripts/sync-service-keys.mjs` (shrinking syncs need `--allow-removals`).
- `scripts/` stays at **zero npm dependencies** — pure Node builtins only.
